# 素材製作

這一頁的內容全部來自實際序列的實測輸出，包括那些後來被證明是錯的估計值。

---

## 1. 來源影片

| | |
|---|---|
| 長度 | 每段 12–25 秒。段落越長，越難均勻抽樣 |
| 解析度 | 生成器給你什麼就是什麼；720p 很常見 |
| 位元率 | 能拿多高就多高——每一個影格最後都會變成一張靜態圖，所以單格細節比串流時更重要 |
| 剪接點 | 別放。捲動序列讀起來是一段連續的運鏡；硬切看起來像 bug |

如果來源是用 image-to-video 模型生成的，鏡頭要鎖住，或是以固定速率移動。飄移的鏡頭在 24 fps 播放時看不出來，但使用者一格一格慢慢推進時非常明顯。

## 2. 超解析度放大

多數生成器上限是 720p。因此在 1920 寬的螢幕上做滿版背景就是 1.5 倍放大，2560 則是 2 倍——會明顯發糊。

`ffmpeg` 的 `scale` 只是內插；它把同樣的資訊攤到更多像素上，沒有增加任何東西。真正要變銳利得靠超解析度。

兩條路，依偏好排序：

1. **專用放大工具**（Topaz Video AI 之類）。frame rate 保持不變——有些預設會偷偷內插到 60 fps，讓影格數翻倍，你算好的每一個索引全部作廢。用高位元率輸出；這是中間檔，檔案大小無所謂。
2. **Real-ESRGAN 4x，再用 Lanczos 降採樣到目標尺寸。** 先放過頭再縮回來，邊緣比直接 1.5x 乾淨。在 CPU 上這很慢——動手前先量：

   | model | 每張 720p 影格秒數（2 核） | 150 影格 |
   |---|---|---|
   | `RealESRGAN_x4plus` | ~397 | ~16.5 h |
   | `realesr-animevideov3` | ~8–20 | ~25–50 min |

   輕量模型快非常多，而且在滿版背景的 1:1 檢視尺寸下，很難分辨差別。放大到 300% 逐像素比對時，重量級模型明顯比較好——但那不是實際的觀看條件。

**只放大你要留下的影格。** 先抽出需要的 N 格，再放大那些。把 24 秒片段的全部 577 格都放大、然後丟掉其中 457 格，純粹是浪費。

## 3. 抽樣

```
index_i = round(i * (total - 1) / (count - 1)),  i = 0 .. count-1
```

`total` 用 `ffprobe -count_frames` 取得；某些容器的 `nb_frames` 標頭會說謊。

不要用 `-vf fps=N/duration`。它會重新取樣時間軸，依進位方式給你 N 或 N+1 個檔案，而且不保證取到真正的第一格和最後一格——而那兩格正是使用者盯最久的。

### 均勻或動態加權

當來源以大致固定的速率運動時，均勻抽樣是正確的。

不是的時候，動態加權比較好。先量每格的變化量：

```bash
python tools/extract_frames.py in.mp4 out/ --count 89 --weighted
#   per-step change: mean 13.42  cv 0.38  below-half steps 8/88
```

`cv` 是每個捲動步進之視覺變化量的變異係數；越低越順。`below-half steps` 計算的是那些讀起來會像卡住的步進數。

在同一段 16 秒來源上實測：

| | 均勻 | 加權 |
|---|---|---|
| cv | 0.73 | **0.38** |
| 卡住的步進 | 29 / 88 | **8 / 88** |

加權預設有阻尼（`--damping 0.35`，即 `w = 0.35 + 0.65·m/mean`）。純比例分配會把刻意安排的安靜節拍刪光；一個靜止的瞬間通常需要幾個影格，才會被感知成一個瞬間。

### 抽樣前先切掉死尾巴

生成出來的片段常常結束在完全凍住的一秒。均勻抽樣之下，那會變成 5–6 個一模一樣的檔案，捲動看起來就在最後卡住。量出來然後切掉：

```bash
# find where motion stops, then
python tools/extract_frames.py in.mp4 out/ --count 61 --end 264
```

## 4. 編碼

| | |
|---|---|
| 格式 | WebP |
| 品質 | 從 72 起跳 |
| `-compression_level` | 6——不損品質，小 2–3%，慢個幾秒 |
| 命名 | `f_001.webp` … 補零、連號 |

決定之前先跑品質階梯：

```bash
python tools/extract_frames.py in.mp4 out/ --count 150 --ladder
```

### 實測數字，讓你的估計一開始就比我們當初準

| 組合 | 格式 | 總計 | 每格 |
|---|---|---|---|
| 150 x 1280x720 | JPEG `-q:v 3` | 10.37 MB | 70.8 KB |
| 150 x 1280x720 | WebP q75 | 4.88 MB | 33.3 KB |
| 150 x 1920x1080，放大 | WebP q72 | 8.04 MB | 54.9 KB |
| 150 x 1920x1080，原生降採樣 | WebP q72 | 12.42 MB | 84.8 KB |
| 120 x 1920x1080，放大 | WebP q65 | 7.17 MB | 61.2 KB |

有三件事值得記牢：

**WebP 省下 53%，不是常被引用的 60–70%。** 那個數字假設基準線是高品質 JPEG。我們的來源已經用 `-q:v 3` 壓過，能省的本來就比較少。

**原生細節比放大出來的細節更佔空間。** 12.42 MB 那組在相同解析度下比 8.04 MB 那組*更大*，因為它帶著真實資訊；放大過的那組比較平滑，所以壓得比較好。這裡小不代表好——小代表裡面東西比較少。

**靠降噪來省位元組在這種素材上行不通。** 輕量的 `hqdn3d` 拿回 7%，代價是看得見的細節流失。當影格裡塞滿細碎的高頻細節時，檔案大小*就是*內容本身。

## 5. 拼接圖（spritesheet）

```bash
python tools/build_spritesheet.py frames/ sheet.webp --cols 9
```

`--cols` 要挑到讓格線接近填滿。120 格排 12 欄剛好 10 列，沒有空格；150 格排 9 欄是 17 列，多出 3 格。

真正的限制是解碼記憶體，不是檔案大小——見 [README](../README.zh-TW.md#the-spritesheet-has-to-be-small-for-a-reason-that-is-not-file-size) 裡的表格。除非你自己量過，否則單格維持 640x360。

150 格、640x360、品質 75 的預期大小：**2.0–2.9 MB**。如果素材充滿高頻細節，你不可能壓到 1.5 MB 以下，而且調降品質救不了你——從 q75 降到 q55 只拿回 20%，卻付出實質的品質代價。改成縮小單格尺寸或減少影格數。

空白格會填黑，但有損 WebP 不會把它們原封不動還原成 0（實測最大值 20–30）。用一個閾值去偵測它們。

## 6. 停留循環

```bash
python tools/make_loop.py hold.mp4 out/ --count 24
```

向生成器要 4–5 秒、鎖定鏡頭、恆定光線、而且只有小幅度的動作。然後去驗證，不要用猜的——工具會回報：

| 量測項目 | 通過標準 |
|---|---|
| 第一格 vs 它所疊在的那個序列影格 | MAE < 3 |
| 整段片段的亮度振幅 | < 5% |
| 鏡頭飄移，第一格 vs 最後一格 | 在 384 寬之下 ≤ 1 px |
| 接點，第一格 vs 最後一格，相對於一個正常步進 | < 1.5x 可直接循環 |

如果第一格對不上底下那個序列影格，切進停留點時會看得出跳動。把序列裡那張確切的靜態圖餵給生成器當第一格，之後再檢查數字。

一次性的進場動畫——例如手臂舉起到最終姿勢——不是循環，也做不成循環。把它拆開：

```bash
python tools/make_loop.py hold.mp4 out/ --count 24 --intro-until 1.9
```

播放器會分別處理 `intro`（播一次）和 `frames`（循環播放）。

## 7. 檢查

沒看過 contact sheet 就不要出貨：

```bash
python tools/contact_sheet.py frames/ survey.png --cols 10 --mark 1,75,150
```

依這個順序檢查：

1. 第 1 格和第 N 格是正確的畫面。
2. 你在意的每個節拍都有覆蓋到——如果序列是繞著幾個 reveal 建構的，每個 reveal 附近都要有影格。
3. 沒有重複。一連串視覺上完全相同的影格，代表抽樣需要修剪或加權。
4. 你的錨定物件（一張桌子、一條地平線、一個產品）沒有飄移或變形。在移動鏡頭的畫面裡，比對錨定物件的裁切區塊，而不是對齊整張影格——鏡頭是刻意在動的時候，整格對齊毫無意義。
